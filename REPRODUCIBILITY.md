# Reproducing and inspecting the saved work

## Verify the completed results first

Run `python3 verify_results.py`, or open notebook 06 in Colab. Verification uses only Python's standard library. It checks every file in the final checkpoint against its saved manifest, the original method/test-plan fingerprints, the 56 prompt/answer records, and their links to the AI-assisted review. It prints the saved summaries; it does not regenerate results or independently validate factual grades.

The final ZIP is deliberately kept byte-for-byte intact. Its original `/content/` paths identify the historical Colab workspace; they are not paths that need to exist just to verify the archive.

## Historical notebooks and recovery

Notebooks 01–05 preserve their downloaded code and outputs. They were built interactively in Colab with uploads and session globals, so opening them and clicking Run all is not a supported clean-start reproduction. Notebook 04 retains a historical missing-`json` error, and notebook 05 retains a missing-`HELDOUT_GENERATION_PLAN_PATH` error from a reset session. Their final experiment artifacts were subsequently recovered and are included in the final checkpoint.

Notebook 07 records the recovery workflow. It expects `trust_detector_backup_20261026T180455Z.zip`, included here, and reconstructs the original plans before completing classifier comparisons and resumable Qwen generation. The final `030637Z` checkpoint is also included so completed generations do not have to be repeated. Preserve an extracted final checkpoint separately before replaying historical reconstruction cells: those cells can rewrite manifests and timing fields. Regenerated bytes and timing need not match the archived run even when settings do.

To replay that historical workflow, open notebook 07 in a fresh Colab runtime and follow its numbered recovery steps. It downloads the pinned models, uses the recorded environment, and can take substantial CPU time. The notebook's checks must pass; do not tune the threshold or attacks using held-out outputs. A rerun is a new execution, not a new untouched test set. The downloaded recovery copy contains source but no saved outputs.

## Recorded model environment

The saved run used Python 3.13-era Colab, PyTorch 2.11.0+cpu, transformers 5.20.2, huggingface-hub 1.33.0, and tokenizers 0.23.3. `requirements.txt` records those model-library versions. CPU float32 and the exact model revisions are part of the experimental setup. Do not replace pinned settings with newer defaults and assume equivalence. The verifier needs none of these packages.

## Interpreting the results

Detection and benign-removal denominators count retrieved occurrences. There are 32 held-out queries for context evaluation, but only eight answerable and eight unanswerable queries for generation per condition/method. Shared prompts reuse a single cached answer. Empty-context policy abstentions are not model generations. Review is AI-assisted and has two unresolved factual judgments; verification preserves grades rather than confirming their correctness. Model generation time excludes downloads and setup; cache timings are not end-to-end detector latency.

## No inference during repository preparation

Repository preparation copied recorded artifacts and ran integrity/count checks only. It did not run Qwen or NLI, alter attack fixtures, retune the threshold, or change answer grades. Existing historical notebook code and outputs are preserved; notebook 06 is a new convenience verifier.
